# 架构与运行语义

## 组件

Vue → Go HTTP API → 运行引擎 / SQLite。生产环境前端静态资源嵌入 Go，页面与 API 同源。

三个后台循环分别处理采集、投递和每小时清理。单实例使用数据目录文件锁；SQLite 单连接，WAL、busy_timeout、NORMAL 同步级别、2 MiB 页缓存和增量回收。迁移拒绝读取更新版本的数据库。

## 数据模型

- Config：revision 控制并发编辑，AES-GCM 加密落库。
- Monitor：来源、间隔、提醒数组、保留策略、启用和草稿状态。
- Rule：触发条件、间隔/时段、冷却、模板、接收方式 ID 列表。
- Recipient：一个人或群组，多个 Method；每个 Method 引用一个 Channel 和可选收件地址。
- Runtime：最新成功值、比较基准、RSS 已见 ID、失败状态及下次运行时间。不受可选历史开关影响。
- records：可关闭的历史；logs：采集/规则/发送阶段的可选执行日志。
- deliveries：持久化待发队列及已完成投递记录，消息是触发时的快照。
- sessions / meta：服务端会话、密码派生、初始化和清理状态。

浏览器不执行后台任务，也不在 localStorage 保存配置或密钥。未保存表单留在内存。并发编辑通过 revision 冲突返回 409，避免覆盖他人修改。

## 采集

调度器取到期任务，获取 worker 槽位及监控锁，校验网络地址，15 秒超时执行，限制响应大小，提取数据并判断。Runtime、可选历史/日志和待发消息在同一事务中写入。

编辑配置后通过 generation 拒绝旧请求结果。来源改变清空比较基准，保留已有历史。入队或保存失败保留旧基准，防止吞掉变化通知。

失败采集不改变成功值；采集退避最多为原间隔 16 倍且不超过 6 小时。手动检查和来源测试同样受 worker 数量限制。

## 时间与投递

整数分钟/小时/24 小时天为间隔。周期和每日定时不受变化冷却影响。重新启用、修改时区或提醒配置会重算；正常重启沿用持久化锚点。

限定时段从每天开始时刻对齐，开始包含、结束不包含，支持跨午夜。间隔不能超过所选时段；跨天周期需选全天。重启补发和队列重试也遵守发送时段，过期消息会跳过。夏令时使用 Go IANA 时区库；缺失/重复本地时刻遵循其时间构造规则，不回放全部错过的发送。

队列 pending → sending → success；失败转 pending 延迟，最多 3 次后 failed；手动重试重新排队。暂停/删除/编辑取消旧代次消息；发送中的外部副作用无法撤回。

60 秒发送租约支持重启恢复，提供至少一次投递。机器人同时校验 HTTP 状态和供应商确认码；普通 Webhook 用 2xx 确认。无法确认成功视为失败。

## 低资源与边界

有界 worker、单数据库连接、响应与模板限制、历史天数/数量、软空间预算、有限队列与重试。日志记录处理后的错误，不保存认证头与原始密钥。Docker 服务日志也有轮转上限。

可选过程日志与必要运行状态分开，关闭日志后仍能看到最新状态。没有浏览器渲染、任意脚本执行、分布式协调或复杂权限体系。

报告先提供数值趋势和 CSV；记录保留采集时间和来源时间，便于后续报表。未保存的历史无法补齐。
